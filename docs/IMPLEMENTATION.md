# Варианты реализации

## A. Локальная база PDF и статический сайт — рекомендованный MVP

Исходники в `sources/`, локальное извлечение текста с проверкой OCR, каталог JSON/Markdown. Сайт — HTML/CSS/JS без сервера.

**Стек:** Python 3.12, PyMuPDF, OCR отдельным шагом для сканов, JSON и Markdown, HTML/CSS/JS.
**Оценка:** 1–2 дня после получения файлов: загрузка и извлечение 2–4 ч, чтение и разбор 19 выступлений 6–10 ч, каталог 3–5 ч.
**Риски:** ошибки OCR, дубли, советы без контекста. Привязывать утверждения к странице PDF.

## B. База знаний Markdown/Obsidian

На каждое выступление отдельная карточка: тезисы, шаги, инструменты, метрики, ограничения, промты и идея навыка.

**Стек:** Markdown, Python для извлечения, Obsidian или любой просмотрщик.
**Оценка:** 1–1,5 дня. **Риски:** менее наглядно для передачи, нужны единые шаблоны и ссылки.

## C. Локальный поиск и Q&A

После проверки корпуса добавить поиск по слайдам и ответы со ссылками на файл и страницу.

**Стек:** Python, SQLite FTS5 для MVP; embeddings — отдельный этап.
**Оценка:** 2–4 дня сверх A. **Риски:** пропуски OCR, ответы без доказательств, утечка закрытых материалов через облачные API.

## MVP-приоритет

Начать с A. Не строить RAG до проверки качества корпуса. Отделять методики спикеров от идей автоматизации, а все фактические тезисы снабжать страницами-источниками.
